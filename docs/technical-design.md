# 技术设计

## 1. 目的

`astro-wechat` 将 Astro 项目中的 Markdown 文章同步到微信公众号草稿箱。

Astro 仍是内容系统与唯一事实来源。该包不会将文章复制到第二个工作目录，也不会编辑文章正文；它会把 Astro 文章适配为规范化文档，渲染兼容微信的 HTML、上传资源，并创建草稿。

初始主要使用方是现有的 AstroPaper 博客仓库；设计不得硬编码该仓库位置，也不得要求使用 AstroPaper 主题。

### 1.1 平台前提

以下两项不是设计选择，而是整个方案能否成立的外部条件。二者均已确认满足，记录于此以便未来换账户或换 CI 环境时重新核对。

| 前提 | 状态 | 不满足时的后果 |
| --- | --- | --- |
| 公众号已获得素材管理与草稿箱接口权限 | 已确认 | 未认证个人订阅号调不通这两类接口，整个包无法工作，只能退化为生成 HTML 供人工粘贴 |
| 具备固定公网出口 IP 的机器，可填入微信 IP 白名单 | 已确认 | GitHub 托管 runner 出口 IP 段轮换，无法列入白名单，CI 自动同步不成立 |

该固定 IP 机器上已运行 `yt_dlp_fastapi` 服务，其上增加一个转发端点，把 Node 构造好的微信请求原样转发出去。CI 仍使用 GitHub 托管 runner。取舍见 ADR-0005 与 CI 集成文档第 7 节。

由此产生一条贯穿全文的约束：**微信协议实现全部在 Node，代理不理解微信。** 下文涉及 access token、素材上传、草稿创建与查找之处描述的都是 Node 侧行为；代理只是一段网络路径。

代价必须一并记住：微信凭据因此存在于 CI 与开发者机器上。ADR-0004 曾用「凭据不进 GitHub」换取跨语言的两套契约同步成本，ADR-0005 反过来选择了前者的代价。

## 2. 设计原则

### 2.1 显式外部写入

创建或更新草稿属于外部副作用，只能通过显式 CLI 或核心库调用发生。Astro 生命周期钩子可以校验内容或准备预览，但不得在 `dev`、`sync` 或 `build` 时发布。

### 2.2 Astro 是事实来源

源 Markdown、frontmatter 和资源保留在 Astro 仓库。生成的微信 HTML 是可丢弃构件，不是第二份可编辑文章。

### 2.3 创建一次，绝不重复

一篇 Astro 文章最多对应一份微信草稿。已同步过的文章重复运行 CI 不做任何操作；创建第二份草稿必须显式覆盖。

**首个版本不实现「更新已有草稿」。** 实际工作流是定时生成新文章后同步一次，已发布文章不会再改动，因此 update 路径服务不到真实需求，却会带来内容哈希比较、图片上传缓存、封面素材替换和更新协调等一整套复杂度。

重复预防仍然必需，因为它服务的是另一件事：同步失败后重试，不能变成建第二份草稿。这只需要「该文章是否已创建过」这一个事实，比完整幂等同步便宜得多。

因此第一版的同步决策只有两种结果：skipped 或 created。

若已同步文章的源内容发生变化，同步器报告一条 drift 警告并跳过，而不是静默无操作 —— 静默会让作者以为改动已生效。这也是保留内容哈希的唯一理由（见第 5.8 节）。

更新路径推迟，接口预留。真正出现「改已发布文章并希望草稿跟进」的需求时再实现，届时哈希、上传缓存和素材替换一并加入。

### 2.4 核心不依赖 Astro 运行时内部实现

CLI 必须能在干净的 Node.js 进程中工作。它应直接解析本地 Markdown 和 frontmatter，而不要求 `astro:content` 等虚拟模块。这让 CI 行为可预测，也使核心将来可以支持其他静态站点仓库。

### 2.5 安全默认值

- 拒绝标记为草稿的文章。
- 在调用微信前拒绝缺少标题或封面的文章。
- 在调用微信前拒绝超出微信限制的字段值。
- 首个版本拒绝 MDX。
- 永不上传或内联 SVG，应先在本地栅格化。
- 不获取任意非图片内容。
- 不记录凭据、access token 或包含密钥的完整 API 响应。
- 可识别已有草稿时，重试不得创建重复草稿。

### 2.6 非目标

首个版本刻意不尝试：向订阅者群发或发布、更新已创建的草稿、跨运行图片上传缓存、MDX 执行或组件渲染、文章生成或改写、托管管理界面、向微信公众号之外的平台发布、保留正文图片动画，以及超出一个默认主题的通用主题系统。

这些条目用于让实现期间的范围压力显式成为本文档的变更，而非未经审查的功能。

## 3. 包的形态

首个版本应是一个 npm 包，而非 monorepo。

| 入口 | 导入说明符 | 职责 |
| --- | --- | --- |
| 核心 | `astro-wechat`（默认导出） | 解析、渲染、资源处理、微信调用与草稿同步 |
| Astro 集成 | `astro-wechat/integration` | Astro 集成工厂 |
| CLI 二进制程序 | `astro-wechat` bin | inspect、preview 与 publish 命令 |

转发代理是独立部署的外部服务，不属于本仓库或 npm 包。Node 代码只通过配置的 HTTPS 地址调用它，不依赖其源码、仓库位置或实现语言。见 ADR-0005。

默认导出必须是与框架无关的核心库，而非 Astro 集成。集成位于独立子路径，因此普通 Node.js 或 CI 使用方永不加载依赖 Astro 的代码。Astro 只是通过该子路径可达的可选 peer dependency。

实现可含内部模块，但使用方不应自行拼装发布流水线。

## 4. 领域模型

### 4.1 SourceArticle

表示规范化前从源文件读取的信息：绝对源路径、项目相对源路径、原始 frontmatter、原始 Markdown 正文和源格式。

### 4.2 ArticleDocument

供渲染和发布消费的规范化文章：稳定源标识符、canonical URL、标题、Markdown 正文、作者、描述/摘要、封面引用、草稿状态、标签和微信同步设置。

locale 与 timezone 有意不在其中：首个版本没有任何使用者，未使用字段会导致实现不一致。真正设计多语言或多账户发布时再加入。

### 4.3 AssetReference

上传前的图片表示：原始源字符串、来源类型（本地、远程、data URI 或已托管微信 URL）、解析后的本地路径或远程 URL、角色（正文图片或封面），以及可选 alt 文本。

### 4.4 RenderedArticle

渲染后的文章分为两个连续状态，因为内容哈希必须在上传前计算。

上传前状态用于跳过决策，包含规范化元数据、含资源占位符的已净化内联 HTML、按顺序排列的正文资源内容哈希和封面哈希，以及内容哈希和哈希 schema 版本。

仅当文章不被跳过时才生成上传后状态：将真实微信资源 URL 替换进已净化 HTML、已上传或复用的封面 media 标识符，以及已上传或复用的资源列表。替换真实 URL 不得改变内容哈希。

### 4.5 DraftIdentity

对应一篇 Astro 文章的微信草稿身份，也是 ADR-0002 中持久化状态存储的单位：稳定源标识符；可用时的 canonical URL（写入草稿 source-URL 字段，也是唯一可从远程恢复的标识符）；已知微信 media 标识符；上次同步内容哈希及 schema 版本；当前封面素材标识符；已记录的孤儿封面素材标识符；以及 `pending` 或 `committed` 写入状态。

`pending` 用于识别微信调用和状态写入之间中断的运行。发现它时应进行协调，而非创建新草稿。

内容哈希在首个版本只驱动 drift 警告，不参与跳过决策；实现 update 路径后它才成为动作依据。

## 5. 内部模块

### 5.1 项目发现

从显式选项或输入文件向上遍历找到 Astro 项目根目录。有效根目录通常同时包含 Astro 配置与包清单；不得假定当前工作目录就是项目根目录。

### 5.2 文章源适配器

加载 Markdown 文件，并把 frontmatter 映射为 `ArticleDocument`。默认兼容 AstroPaper 的映射：

| Frontmatter 字段 | 文章字段 |
| --- | --- |
| `title` | title |
| `description` | digest |
| `author` | author |
| `ogImage` | cover |
| `draft` | draft status |
| `tags` | tags |
| `canonicalURL` | canonical URL |
| `wechat` | synchronization settings |

`pubDatetime`、`modDatetime`、`timezone` 等未映射 AstroPaper 字段可读取但不带入 `ArticleDocument`，因为下游没有消费它们。

标题优先级：显式 CLI 覆盖、`wechat.title`、frontmatter `title`、第一个 Markdown H1。

封面优先级：显式 CLI 覆盖、`wechat.cover`、frontmatter `ogImage`、项目默认封面、校验错误。

若 Markdown 正文首个 H1 与解析后的标题重复，适配器可移除该标题，避免微信正文重复。

#### 字段限制校验

微信会拒绝过长字段而不是截断。适配器必须在上传或创建草稿前按微信限制进行本地校验：标题和作者超限即报错；摘要在词或句子边界截断并警告；正文 HTML 超限即报错且报告测得大小。

具体数值须在实现时从最新微信官方文档读取，放入一个共享常量模块，不能在校验器中复制；本文不写入数值，以避免过时信息。摘要缺失时，从去除 Markdown 后的正文开头推导，再应用相同截断规则。

### 5.3 资源解析器

无需 Astro 构建即可解析 Astro 风格资源引用，支持：相对 Markdown 文件的路径、项目 `public/` 下路径、如 `/images/cover.png` 的站点根路径、显式允许时的绝对文件系统路径、HTTP/HTTPS URL，以及受配置限制的 data 图片 URI。

某些 AstroPaper 文章的 `ogImage` 在 `public/` 前含额外父级路径。为兼容，解析器应识别 `public/` 后缀并从发现的 Astro 根目录解析；由于路径有歧义，必须警告，不能对所有相对路径静默应用该回退。

### 5.4 Markdown 渲染器

将 Markdown 正文转换为确定性的微信兼容 HTML。初始支持当前 AstroPaper 文章所用的稳定 CommonMark/GFM 子集：标题、段落与换行、强调和删除线、有序/无序列表、引用、链接、图片、围栏代码块、表格、水平线、所选解析器支持时的脚注，以及受限的原始 HTML。

渲染器应沿用先前 `wechat_posts` 项目的流水线形态：

1. 将 Markdown 解析为 HTML。
2. 改写出站链接。
3. 应用面向微信的主题。
4. 内联 CSS。
5. 净化不支持和不安全的 HTML。
6. 强制响应式图片样式。

在从该项目衍生任何代码前，必须记录其仓库 URL 和许可证，并由开放决策 3 的审查批准。在此之前，`wechat_posts` 仅是流水线顺序参考，不是代码来源。

仓库：_待记录_。许可证：_待记录_。

渲染器必须作为可调用的库函数导出，不得依赖子进程或通过 stdin/stdout 通信。

#### 出站链接处理

微信文章正文不会将任意外部超链接渲染为可点击链接。`[text](https://example.com)` 会无声丢失目标地址，这是内容正确性问题而不只是样式差异。

渲染器不得输出平台会丢弃目标地址的锚点。默认策略：微信接受的目标保留为锚点；其他链接渲染为可见文本，加上上标参考编号并收集至文章末尾的参考列表；重复目标共用一个编号；已作为文本可见的自动链接和裸 URL 不重复加入参考列表；参考列表标题和允许的目标规则属于主题级配置，但转换本身不可选。

Markdown 脚注和生成的链接引用共用一个编号空间，避免同一文章出现冲突的两套参考列表。首个版本提供一个克制的默认主题；渲染契约和视觉快照稳定后再增加主题。

### 5.5 HTML 资源收集器

使用 HTML 解析器而非正则表达式从渲染 HTML 中收集图片。它先将每个图片源改写为由图片内容哈希导出的稳定占位符以便哈希，上传后再替换为真实微信 URL，同时保留相关 alt 文本和安全展示属性。

占位符使上传前哈希有明确的定义。两次处理都使用同一解析器，保证替换不会扰动周边标记。Markdown 图片和允许的原始 HTML 图片因在 Markdown 渲染后处理而共享同一路径。

### 5.6 图片处理器

使用 `sharp` 或同等 Node 图片管道规范化微信图片。

- 接受 PNG、JPEG、WebP、GIF 和 SVG 源。
- 为 JPEG 输出铺平透明度。
- 约束尺寸和字节大小。
- 校验解码后的图片内容，不信任文件扩展名。
- 将每张图片规范化为目标微信端点接受的格式。

#### 输出格式由端点决定，而非源格式

微信正文图片端点接受的格式少于本包读取的源格式。因此可接受的源格式只是输入便利，不保证原样透传；每张图片均须在上传前解码并重新编码为允许的输出格式。

- 动态 GIF 和动态 WebP 无法保留，会缩减为第一帧，并对每张受影响图片警告一次。此前“仅在明确支持时保留动画”的说法撤回，因为平台不支持正文图片动画。
- SVG 永不上传且永不内联到文章 HTML，而是在受限目标尺寸下本地栅格化。栅格化必须禁用外部实体解析、远程引用和脚本，防范 XXE 与脚本注入。
- 无论源格式如何，封面都要重新编码为可接受的永久素材格式。

具体接受格式列表须在实现时从最新官方文档读取，并与字段限制同放入共享常量模块。

#### 缓存

首个版本只需要一个缓存：

| 缓存 | 键 | 生命周期 | 用途 |
| --- | --- | --- | --- |
| 解码/转换缓存 | 源内容哈希加转换参数 | 单次命令执行 | 避免一次运行内重复下载和重新编码 |

跨运行的持久化上传缓存**不在首个版本范围内**。它存在的意义是避免更新草稿时重传未变化图片，而首个版本不更新草稿：每篇文章一生只上传一次图片。唯一的重复上传发生在失败重试时，浪费有限且可接受。

实现 update 路径时必须同时加入上传缓存，否则每次更新都会重传全部正文图片。因此图片上传须走一层可替换的接口，而不是直接调用客户端，使后续接入缓存不必改动调用方。

缓存未命中绝不能报错；缓存过期或不可用时退化为重传，消耗配额但保持正确。

远程下载必须限制超时、重定向次数和最大字节数，校验 MIME，并防止访问 loopback、link-local 和私有网络地址。

### 5.7 微信客户端

封装同步所需的官方微信操作：获取 access token、上传正文图片、以永久素材上传封面、创建草稿、在协调时按 source-URL 查找草稿。全部实现在 Node 侧。

更新草稿的接口不在首个版本实现，理由见第 2.3 节。客户端的方法集合应保留其位置，但不提供未经测试的实现。

必须分别表示传输错误与微信应用错误。**HTTP 200 不等于操作成功**，始终检查响应体中的错误码。这是本模块最容易写错的一处，测试必须直接覆盖。

#### 请求出口

客户端不直接决定网络路径。配置了代理地址时，请求发往代理并由它转发；未配置时直连 `api.weixin.qq.com`（ADR-0005 第 5 条）。

代理不理解微信，因此对客户端而言两种模式下的响应完全一致，错误处理逻辑不分叉。唯一的区别是代理自身的失败——不可达、认证失败、路径不在白名单——必须与微信返回的错误区分开：前者是运维问题，后者是业务问题。

#### Access token 获取

一个账户同一时刻只有一个有效 access token，普通 token 接口的获取会使此前 token 失效。CI job 与开发者本地运行同时获取会互相驱逐，表现为看似限流的间歇认证失败。

因此必须使用面向多并发调用方的 stable-token 接口，不能以普通 token 接口作为回退。

需要清楚的是这是约定而非结构性保证：ADR-0004 曾让网关成为唯一调用方，从而在结构上消除互踢；ADR-0005 放弃了那条路径，现在只能靠 stable-token 加按账户划分的 CI 并发组。

token 规则：绝不写入日志、构件、清单或预览输出；持久化缓存默认关闭，启用后仅所有者可读且按 AppID 分键；必须允许受限速的强制刷新，以免重试循环耗尽刷新配额。

#### 永久素材生命周期

封面作为永久素材上传，受每账户总配额限制，且上传后不会被任何草稿操作回收。

首个版本不更新草稿，因此不存在「换封面导致旧素材成为孤儿」这条路径。孤儿只来自一种情况：封面已上传成功，但随后的草稿创建失败或结果不明。该素材已经占用配额，却不属于任何草稿。

因此必须：

- 封面规范化内容哈希未变时复用现有素材，使重试不会重复上传。素材标识符记在 Node 侧台账，因为只有它知道文章身份。
- 封面上传成功后立即记录其标识符，早于草稿创建调用。创建失败时该记录就是孤儿凭据。
- 提供显式 opt-in 的孤儿封面素材清理命令。

删除素材不可逆，因此有两道闸：普通 publish 绝不隐式清理，且代理的删除素材路径默认不在白名单内（转发代理契约第 3 节）。运维时先在代理放行该路径，清理完再收回。

#### API 配额

微信对每个接口施加每日调用配额。批量发布的多篇文章和多张图片会迅速消耗配额。

客户端必须把剩余配额和配额耗尽错误码识别为独立的错误类别。配额耗尽不得按瞬态错误重试 —— 重试只会更快耗尽额度，并把一个可解释的运维问题变成一串看不懂的失败。

### 5.8 草稿同步器

负责重复预防，并决定跳过还是创建。首个版本没有第三种结果。

#### 决策依据是身份，不是内容

跳过与否只取决于一个事实：该稳定源标识符是否已有 committed 的草稿记录。有则跳过，无则创建。内容哈希不参与这个判断。

这是第 2.3 节「不实现 update」的直接结果，也是本节相对完整幂等同步大幅简化的地方：不需要比较哈希来决定动作，只需要查一条记录是否存在。

#### 内容哈希只用于 drift 警告

哈希仍然计算并记录，用途仅一个：已有 committed 记录且哈希与记录不符时，报告一条 drift 警告，说明源文章在同步后被改过而草稿不会更新。文章仍然跳过。

没有这条警告，作者改完文章重跑 CI 会看到一次静默的 skipped，误以为改动已生效。

哈希必须在任何上传之前可计算，否则一条纯提示信息会消耗上传配额。故哈希仅覆盖：规范化稳定源标识符、字段限制校验后的标题/作者/摘要、资源仍为占位符的已净化 HTML、按顺序排列的规范化正文图片内容哈希、规范化封面内容哈希、渲染器与主题版本、哈希 schema 版本。

上传的微信 URL 与 media 标识符不参与哈希；替换真实 URL 不得改变哈希。这些约束在 update 路径实现后会重新变成正确性要求，而不只是性能要求，因此现在就必须遵守。

#### 顺序

1. 恢复已有草稿身份。存在 committed 记录则跳过，不解析资源、不渲染、不上传。
2. 否则在本地解析并规范化资源、计算其内容哈希，不进行网络写入。
3. 渲染包含资源占位符的已净化 HTML。
4. 计算内容哈希。
5. 写入 pending 记录，包含源身份与内容哈希。
6. 上传资源，替换真实 URL。
7. 创建草稿。
8. 将记录标记为 committed，写入返回的 media 标识符。

第 1 步先于渲染，因为已同步文章的常见情况是完全无事可做，不值得为它渲染和解析资源。drift 警告需要哈希，因而需要渲染，所以它是一个可配置项：默认开启，可关闭以换取批量运行时的速度。

#### 结果不明的创建

第 7 步超时且结果未知时，绝不能直接重试创建。下一次运行会发现 pending 记录，据此触发协调：按 source-URL 字段扫描远程草稿，确认上一次是否实际成功。

这是首个版本仍然需要两阶段写入和远程扫描的唯一原因，也是「重试不产生重复草稿」这一真实需求的落点。

#### 草稿身份

源标识符优先采用 canonical 文章 URL，回退为规范化项目相对源路径。微信草稿没有自定义元数据；列出草稿只返回文章字段，因此唯一可持久化稳定身份的载体是同步器写入 canonical URL 的 source-URL 字段。标题可编辑且不唯一，不能用于匹配。

草稿列表分页且返回完整文章，扫描查找一篇文章的成本随草稿箱线性增长；没有 canonical URL 的文章没有可远程恢复身份。故远程扫描只用于重建本地记录或解决写入歧义，稳态查找依赖持久化本地记录。

临时 CI 中本地状态不够。持久化状态、协调步骤与远程扫描上限由 ADR-0002 决定，里程碑 3 开始前必须接受该 ADR。

## 6. Frontmatter 合约

建议的可选 `wechat` 对象：

| 字段 | 用途 | 默认值 |
| --- | --- | --- |
| `enabled` | 允许自动同步 | `false` |
| `title` | 微信专用标题覆盖 | 文章标题 |
| `cover` | 微信专用封面 | `ogImage` 或项目默认值 |
| `author` | 微信专用作者 | 文章作者/项目默认值 |
| `digest` | 微信专用摘要 | 文章 description |
| `sourceURL` | 显式规范源 URL | 派生 canonical URL |

未来可加入评论设置、主题选择和 locale。除非明确选择基于仓库的状态，草稿 media 标识符和同步哈希不应放进普通文章 frontmatter。

### 6.1 符合条件的优先级

frontmatter `wechat.enabled` 与项目配置的符合条件标签/源路径是两个独立门槛。二者以 AND 合并，并且文章级门槛权威：

1. `draft: true` 排除文章；配置中没有覆盖方式，只有显式 CLI 标志可覆盖。
2. `wechat.enabled` 必须为 `true`；项目配置不能让文章 opt-in。默认是 `false`，所以未声明不会发布。
3. 配置的符合条件标签和源路径进一步缩小集合，可排除已 opt-in 文章，但不能纳入已 opt-out 文章。

携带 `wechat.enabled: true` 但被配置排除的文章，须以具名原因报告为 skipped，不能静默省略，因为该组合通常表示配置错误。

Astro 集成应导出 schema 片段或辅助函数，使 Astro 项目内容 schema 能校验该对象而不复制其形态。

## 7. CLI 合约

| 命令 | 外部写入 | 用途 |
| --- | --- | --- |
| `inspect` | 否 | 显示规范化文章元数据和校验结果 |
| `preview` | 否 | 生成本地独立 HTML 预览 |
| `list` | 否 | 列出可发现且启用同步的文章 |
| `publish` | 是 | 同步一篇或多篇显式 Markdown 文件 |
| `publish-changed` | 是 | 同步两个 Git 修订间变更的符合条件文件 |
| `cleanup-orphans` | 是 | 仅在 opt-in 时删除已记录的孤儿封面素材 |
| `verify-proxy` | 否 | 使用伪微信凭据验证已部署代理的认证、白名单与原样透传 |

两个 publish 命令均须支持 `--dry-run`：它执行到创建决策为止，包括草稿身份查找、资源解析、渲染和哈希，随后报告计划操作，不上传或写入。`inspect` 和 `preview` 无法替代它，因为二者不查询草稿身份，也就无法回答「这篇会被跳过还是会新建」。

所有命令除人类可读日志外都必须提供机器可读输出。CI 必须无需解析文字即可区分 skipped、created 与 failed。首个版本没有 updated 状态；该值保留给未来的 update 路径，消费方不应假定状态集合封闭。

可能产生破坏或重复的行为须显式标志：

| 标志 | 作用 | 风险 |
| --- | --- | --- |
| 允许源文章为 draft | 忽略 `draft: true` | 发布未完成内容 |
| 强制创建 | 对已有 committed 记录的文章再建一份草稿 | 草稿箱出现重复文章，须手动清理 |

「绕过内容未变检测」不再作为标志存在，因为首个版本的跳过依据是身份而非内容。

## 8. 配置

项目配置可定义内容目录、站点 URL、默认作者、默认封面、主题、图片限制、远程图片策略、符合条件的标签或源路径（受第 6.1 节优先级限制）、按 ADR-0002 选定的持久化状态位置和预览输出目录。

密钥仅存在于环境变量，且两侧持有的东西不同：

| 变量 | 必需性 | 说明 |
| --- | --- | --- |
| `WECHAT_APP_ID` | 发布时必需 | 公众号 AppID |
| `WECHAT_APP_SECRET` | 发布时必需 | 公众号 AppSecret |
| `WECHAT_PROXY_URL` | CI 必需，本地可选 | 转发代理地址，必须是 HTTPS。未设置时直连微信 |
| `WECHAT_PROXY_TOKEN` | 设置了代理地址时必需 | 代理 Bearer 令牌，可独立于微信凭据轮换 |

微信凭据存在于 CI 与开发者机器上。ADR-0005 明确接受了这个代价，缓解措施只能是常规做法：存在受保护的 environment 中、只暴露给同步 job、定期轮换。

配置文件、frontmatter、生成清单、日志和预览 HTML 绝不能包含 AppSecret、access token 或代理令牌。CLI 与 Astro 集成必须消费同一份已解析项目配置，避免各自配置副本漂移。

## 9. 错误与重试策略

错误分为六类：

1. 源校验：缺少元数据、字段限制违规、草稿禁用、不支持 MDX。
2. 资源处理：路径无法解析、图片无效、不安全远程 URL。
3. 渲染：语法不支持或输出无效。
4. 微信传输/应用：认证、上传或草稿操作失败。
5. 配额：每日接口配额或永久素材配额耗尽。
6. 代理：转发代理不可达、令牌无效、路径不在白名单。

第 5 类独立于第 4 类，因为重试会可靠地使其更糟。它必须作为可操作的错误报告，不能进入退避循环。

第 6 类独立于第 4 类，因为修复方式完全不同：代理故障是运维问题，与公众号本身是否健康无关。把二者混为一谈会让人在微信后台查一个其实出在自己服务器上的问题。

仅重试安全操作：受限刷新频率的 token 获取、远程图片下载、可协调结果的图片上传，以及带瞬态状态或文档声明可重试错误码的微信请求。草稿创建在超时结果不明后绝不能盲目重试，必须先协调以避免重复草稿。

批量发布应报告每篇文章结果；任一请求同步失败即以非零退出。成功同步的文章保持成功状态，而非在概念上回滚。

## 10. 安全

- 凭据只来自进程环境或刻意配置的 secret provider。
- 转发代理的目标主机写死在其配置中，绝不从请求读取。一个能转发到任意主机的代理就是开放代理，可被用来从该 IP 攻击第三方或 SSRF 进内网。
- 代理按路径白名单放行。因为微信侧有 IP 白名单，代理访问权就是操作公众号的能力边界，白名单直接限定了令牌泄露后的爆炸半径 —— 其中没有群发接口。
- 代理的删除素材路径默认不在白名单内。
- 代理只接受 HTTPS，令牌比较使用常量时间实现，请求体大小设上限。
- **代理绝不记录 query string 与请求体**：`access_token` 在 query 里，AppSecret 在 token 请求的 body 里，一行普通 access log 就足以把两者落盘。
- 日志会脱敏可能含 token 的查询参数和响应字段。
- 启用 token 缓存时使用仅所有者权限。
- 远程图片获取拒绝非 HTTP scheme 和私有网络目标。
- 限制下载大小和图片解码大小。
- SVG 在禁用外部实体、远程引用和脚本的情况下栅格化，绝不内联或上传。这条约束适用于**每一条**把 SVG 变成像素的路径，包括 `data:image/svg+xml` 内联形式 —— 只按文件扩展名判断会漏掉它，从而绕过检查直接交给通用图片管道。
- 提交前净化原始 HTML。
- 首个版本拒绝 MDX 和任意组件执行。
- 删除永久素材不可逆，孤儿清理是独立 opt-in 命令，永不属于发布流程。
- CI 发布只运行于可信分支，绝不运行不可信 pull request 代码。
- 微信 job 应使用密钥范围严格的 environment。

## 11. 测试策略

### 11.1 单元测试

- frontmatter 映射与优先级
- `draft` 和 `wechat.enabled` 过滤
- 项目及 public 资源解析
- canonical URL/源标识符生成
- 远程 URL 安全检查
- 字段限制校验和摘要截断
- 出站链接改写与参考列表编号
- 内容哈希稳定性，以及其与上传资源 URL 无关（直接断言，防止回归为上传后哈希）
- 微信错误响应解析和不可重试的配额分类
- `wechat.enabled` 与配置过滤器的符合条件优先级
- 同步决策：已有 committed 记录则跳过，无记录则创建，pending 记录则协调
- 源变更后产生 drift 警告且仍然跳过

### 11.2 渲染快照

fixture 应覆盖标题、列表、链接、表格、代码块、引用、脚注、本地图片和原始 HTML。快照变化必须作为可见发布变更审查。

### 11.3 图片测试

fixture 应包括透明 PNG、JPEG、WebP、SVG、超大图片、错误 MIME 声明和无效数据。

### 11.4 微信契约测试

只有一套。mock HTTP server 直接扮演微信，测的是真实的微信契约，而不是我们自己发明的中间契约 —— 这正是 ADR-0005 相对 ADR-0004 换来的东西。

必须覆盖：

- token 获取与过期后重新获取
- 正文图片上传、封面上传、草稿创建的成功路径
- **HTTP 200 中返回 `errcode`**，确认不被当作成功
- 瞬态状态码的重试
- 配额错误码归入独立类别且不重试
- 草稿创建超时且结果不明，确认不发生盲目重试
- 按 source-URL 查找草稿，包括分页与扫描上限

代理只需少量测试：请求经代理转发后与直连产生相同的解析结果，以及代理自身的失败（不可达、认证失败、路径被拒）与微信错误可区分。代理不理解微信，因此不需要为它复制上面那张表。

默认测试套件绝不要求真实微信凭据。

还必须覆盖：

- 已同步文章重复运行时零请求，通过统计 mock 请求断言，而非检查日志
- 创建超时后的第二次运行进行协调并跳过，不产生第二份草稿
- 封面上传成功但草稿创建失败时，该素材被记录为孤儿
- 重试时按内容哈希复用已上传封面
- 同账户两次同步串行而不交错
- 配额耗尽不重试
- 按 source-URL 恢复草稿身份，包括分页扫描回退及扫描上限

默认测试套件绝不要求真实微信凭据。

### 11.5 AstroPaper 兼容性测试

维护经净化的代表性 fixture：没有正文 H1 的技术日报、没有封面的 GitHub 日报、带本地 WebP 封面的播客文章、带 SVG 封面（断言本地栅格化且 mock 微信服务器不收到 SVG）的 Hacker News 文章、带多张远程图片的媒体推荐文章、含多个外部 Markdown 链接（断言参考列表输出）的文章，以及含动态 GIF（断言缩减为第一帧并警告）的文章。

## 12. 兼容性与版本

初始目标：Node.js 22+、ESM、当前稳定 Astro 大版本（首个稳定版前评估前一个大版本）、普通 `.md` 内容条目。

本文不写死 Astro 大版本号；实现集成时须按实际发布状态确认，并记录在 package manifest 的 peer dependency 范围中，这是必须准确的唯一位置。核心和 CLI 按第 3 节入口拆分，在未安装 Astro 时仍可使用；集成将 Astro 声明为可选 peer dependency。

规范化元数据、渲染 HTML、主题输出、源身份或哈希规则的变更都影响兼容性，必须提供发布说明。

源身份规则的变更影响最大：它决定已同步文章能否被识别，改动后旧记录会全部失配，下次运行将为每篇文章再建一份草稿。此类变更必须提供状态迁移，不能只写发布说明。

内容哈希输入变更须递增 hash schema version。在首个版本中其影响仅限于 drift 警告失真，不会触发任何写操作；实现 update 路径后，同一变更将导致所有草稿被重写，届时该条目的严重性上升，发布说明必须相应改写。

## 14. 开放决策

### 14.1 已确认

| 决策 | 结论 |
| --- | --- |
| 公众号接口权限 | 已具备素材管理与草稿箱权限；见第 1.1 节 |
| 固定出口 IP | 已具备；该机器上的转发代理负责出口，微信协议实现留在 Node，CI 仍用托管 runner；见 ADR-0005 |
| 编辑是否更新已有草稿 | 首个版本不更新，只做重复预防；见第 2.3 节 |
| 渲染器与微信 SDK 是否复用现成项目 | 均自研；主题隔离为可替换 CSS 资产；见 ADR-0003 |

前两项在换账户或换 CI 环境时须重新核对。第三项在出现「改已发布文章并希望草稿跟进」的真实需求时重新打开。第四项含一份待核实清单，见 ADR-0003。

### 14.2 待确认

在实现达到对应里程碑前，必须确认：

1. 临时 CI 中如何恢复草稿身份与写入状态；已由 ADR-0002 限定，里程碑 3 前须接受。
2. 首个渲染器独立实现，还是在许可证审查后从现有项目衍生代码；确定前，第 5.4 节的 `wechat_posts` 不携带代码。
3. 哪些 AstroPaper 定时任务类型设置 `wechat.enabled: true`。
4. 微信仍会渲染为可点击锚点的目标类型，从而确定第 5.4 节链接策略的例外列表；确认前，安全默认值是将所有外部链接加入参考列表。
5. 共享常量模块所用的确切微信字段限制、允许上传格式和配额值。
   其中一项单独点名：草稿列表接口在 `no_content: 1` 时是否仍返回
   `content_source_url`。它是协调路径匹配草稿的唯一依据，猜错会让匹配永远失败。
   代码里已有判别逻辑，字段缺失时立刻报错而不是继续扫描，但正确的参数取值仍需实测确认。
6. 首次公开预发布前完成 ADR-0003 剩余的微信排版库生态检索。
